A fresh collection.
Every morning.

Choose the photos you love once. Your iPhone can send a different selection to the frame each day.

Photos album → Daily Shortcut → Your frame

1. Make your album

In Photos on your iPhone, create an album named Dash Frame. Add the pictures you would like to see. The Shortcut chooses up to 24 at random; adding more gives you a different mix each day.

Still photos work best. Live Photos can be converted to still JPEGs; exclude videos. Portrait photos fill the display using a crop you can adjust in Apps → Photos.

2. Connect your frame

Deploy the photo functions to your existing Convex project and set its private DASH_FRAME_TOKEN environment variable. Enter that same token in Apps → Photos → Connection on Dash, together with the deployment's .convex.site URL.

This page fills in your configured URL when available. Photo requests use .convex.site; existing phone-status Shortcuts continue using .convex.cloud.

The photo token is shown only when you set it up. Dash saves it privately and never returns it to this page. Keep the same token in the Shortcut described below.

3. Build “Send photos to Dash”

In Shortcuts, create a new shortcut named Send photos to Dash. Use these actions in order. Wherever a value is in square brackets below, insert that action's magic variable, rather than typing the brackets.

  1. Add Text containing your photo token; use Set Variable to name it Photo Token.
  2. Add Find Photos: Album is Dash Frame, Media Type is Image, Sort by Random, Limit 24. If it says Filter Photo Token, tap that input variable and choose Clear so it searches All Photos. Add Set Variable, name it Selected Photos, and select the Photos output.
  3. Count Selected Photos. If the count is 0, use Stop This Shortcut. Otherwise save the count as Photo Count.
  4. Add Generate UUID and save it as Request ID. Add Current Date → Format Date with custom format yyyy-MM-dd; save it as Batch Date.
  5. Get Contents of URL using the start request below. Choose a JSON request body and add its three fields individually. Add expected_count as a Number field. Immediately afterward, add Get Dictionary Value: key batch_id, dictionary Contents of URL from this start request. Add Set Variable: name Batch ID, value Dictionary Value. Batch ID is returned by Convex; Request ID is the UUID you generated earlier. Add If Batch ID does not have any value → Show Result with the start request's Contents of URL → Stop This Shortcut → End If.
POST /frame/batches/start
Headers:
  Authorization: Bearer [Photo Token]
  Content-Type: application/json
JSON fields:
  request_id: [Request ID]
  expected_count: [Photo Count]
  date: [Batch Date]
  1. Add Repeat with Each item in Selected Photos. First inside the loop, add Convert Image: input Repeat Item, format JPEG, high quality, Preserve Metadata off. Add Set Variable: name SourceJPEG, value Converted Image from this action. Convert before resizing: testing on the iPhone found an empty resize result for a Photos item that worked when converted to JPEG first.
  2. Use Get Details of Images to get Width and Height from SourceJPEG. Set Resized Photo to SourceJPEG first. If either dimension exceeds 2048, add an inner If Width is greater than Height: Resize Image with input SourceJPEG, width 2048, height Auto. In Otherwise, resize SourceJPEG to height 2048, width Auto; this also handles square photos. Immediately after each Resize action, add Set Variable to assign Resized Photo the Resized Image output from that same branch. End both If blocks. Smaller photos keep SourceJPEG.
  3. Add Convert Image: input Resized Photo, format JPEG, quality approximately 80%, Preserve Metadata off. Add Set Variable: name Upload Photo, value Converted Image from this final conversion.
  4. Calculate Repeat Index minus 1; use Set Variable to save the Calculation Result as Photo Index. Send the upload request below. In Get Contents of URL, choose Request Body → File, tap the File input, and select the Upload Photo variable. This sends the JPEG's actual contents. After the request, add Get Dictionary Value: key id, dictionary Contents of URL from this upload request. Add If Dictionary Value does not have any value → Show Result with the upload request's Contents of URL → Stop This Shortcut → End If. For depth effect, use the separate worker Shortcut in step 4. Keep this upload loop JPEG-only.
POST /frame/photos/upload?batch_id=[Batch ID]&index=[Photo Index]
Headers:
  Authorization: Bearer [Photo Token]
  Content-Type: image/jpeg
Request Body: File → [Upload Photo]
  1. After End Repeat, send the commit request below. This makes the complete collection available to Dash. Optional: show a notification only after a successful commit.
POST /frame/batches/commit
Headers:
  Authorization: Bearer [Photo Token]
  Content-Type: application/json
JSON fields:
  batch_id: [Batch ID]

Each photo must be a JPEG under 8 MiB. Delete any empty header rows: a blank header reproduced “The network connection was lost” in Apple's networking API. If a request fails, the old collection stays on screen. You can run the Shortcut again; unfinished batches are cleaned up automatically.

4. Add depth with a separate worker Shortcut

Requires Dash 2.4.0 and the updated Convex functions. Keep Send photos to Dash as a JPEG-only uploader: remove the entire Remove Background / foreground-upload block from its Repeat. Keep its existing JPEG uploads, End Repeat, and final commit request. The collection appears as soon as all JPEGs are committed.

Create a second Shortcut named Process one Dash foreground. Each run claims just one photo from the current collection. A failed Remove Background action may still stop this run; it cannot stop the separate upload or the other scheduled worker runs. You need two Shortcuts total, even with 25 automations.

  1. Add Text containing your existing photo token. Add Set Variable: name PhotoToken, value that Text output. Keep the token private; it goes only in the Authorization header.
  2. Add Generate UUID, then Set Variable: name WorkerRequestID, value that UUID output. This identifies this claim request; it is not the batch ID or attempt ID.
  3. Add Get Contents of URL using the claim request below. Choose POST, add the two headers, and choose Request Body → JSON. Add one Text field named exactly request_id; its value is the WorkerRequestID variable. Delete any empty header rows.
POST /frame/foregrounds/claim
Headers:
  Authorization: Bearer [PhotoToken]
  Content-Type: application/json
Request Body: JSON
  request_id: [WorkerRequestID]
  1. Add Set Variable: name ClaimResponse, value Contents of URL from the claim request. Add Get Dictionary Value: key error, dictionary ClaimResponse. Add If Dictionary Value has any value → Show Result with that error → Stop This Shortcut → End If.
  2. Add Get Dictionary Value: key attempt_id, dictionary ClaimResponse. Add Set Variable: name AttemptID, value this Dictionary Value. Add If AttemptID does not have any value → Stop This Shortcut → End If. This is a normal no-op when no unattempted photos remain or no collection is ready.
  3. Add three more Get Dictionary Value / Set Variable pairs. Each dictionary must explicitly be ClaimResponse: key batch_id → variable BatchID; key index → PhotoIndex; key photo_id → PhotoID. These values come from Convex. Do not generate them or subtract 1 from this index.
  4. Add Get Contents of URL: /frame/photos/[PhotoID]. Replace [PhotoID] with its variable chip. Set GET and header Authorization to Bearer followed by the PhotoToken chip. Add Set Variable: name WorkerPhoto, value this GET request's Contents of URL. This downloads the exact JPEG already on the frame. Do not resize it again.
  5. Add Get Details of Images: Width of WorkerPhoto → Set Variable BackgroundWidth. Repeat for Height → BackgroundHeight.
  6. Add Apple's Remove Background, with WorkerPhoto as its image. If a crop-to-subject option is offered, leave it off. Add Set Variable: name ForegroundImage, value this action's output. Add If ForegroundImage does not have any value → Stop This Shortcut → End If. If removal itself throws an error, let this worker run stop.
  7. Add Convert Image: input ForegroundImage, format PNG, Preserve Metadata off. Add Set Variable: name ForegroundPNG, value this PNG action's Converted Image. Get its Width and Height with two Get Details of Images actions, saving ForegroundWidth and ForegroundHeight.
  8. Add If with Any conditions: ForegroundWidth is not BackgroundWidth, ForegroundHeight is not BackgroundHeight. Inside, add Stop This Shortcut, then End If. Cutouts must keep the full original canvas and subject position.
  9. Add Get Contents of URL with the upload request below. Insert the BatchID, PhotoIndex, and AttemptID variable chips in the URL. Set POST, the two headers below, and Request Body → File. Tap the File input and select ForegroundPNG. The PNG must have transparency, visible foreground pixels, and be under 20 MiB.
POST /frame/foregrounds/upload?batch_id=[BatchID]&index=[PhotoIndex]&attempt_id=[AttemptID]
Headers:
  Authorization: Bearer [PhotoToken]
  Content-Type: image/png
Request Body: File → [ForegroundPNG]
  1. Add Get Dictionary Value: key id, dictionary Contents of URL from this PNG upload. Add If Dictionary Value does not have any value → Show Notification with this upload's Contents of URL → End If. There is no Repeat and no commit request in this worker. A successful PNG upload completes the attempt automatically.

Convex records the attempt before returning the photo. Other worker runs immediately move to other photos, even while this one is processing. If no accepted PNG arrives within five minutes, the attempt becomes timed_out. That means no result was received, not proof the image lacks a subject. Expired attempts are not automatically retried; their photos stay on the frame normally. A new JPEG collection creates a fresh set of attempts. Late uploads for an expired attempt or a collection that is no longer active are rejected.

If retrying an interrupted HTTP request within the same worker, reuse its saved WorkerRequestID or upload URL so the request stays idempotent. Starting the worker again generates a new UUID and claims the next unattempted photo.

After one successful worker run, allow roughly 90 seconds for the server and browser polls, or use the Photos sync control. In Apps → Photos, select that photo, enable Depth effect, adjust the clock, and save. Depth starts off per photo. New cutouts preserve the current rotation position; photos without cutouts remain usable.

5. Try it, then make it daily

Run the Shortcut manually once, allowing Photos and network access when iOS asks. Check Apps → Photos for the new collection. Dash checks for new photos every minute and downloads the complete set before showing it.

In Shortcuts → Automation, create a Time of Day automation at a convenient morning time, repeating Daily. Choose Run Immediately and run Send photos to Dash. It may take longer when iCloud needs to download selected originals.

For depth, first run Process one Dash foreground manually after the JPEG upload has committed. Then test a separate Time of Day automation while the phone is locked. An Apple action error may still produce an iOS error notification; the other runs remain separate.

Example daily schedule: 7:00 AM → Send photos to Dash. Add 24 separate Time of Day automations, every two minutes from 7:10 AM through 7:56 AM, each set to Daily → Run Immediately → Process one Dash foreground. All 24 use the exact same worker Shortcut, with no input. Leave enough time after the first automation for your JPEG upload to finish. With fewer than 24 photos, the extra workers stop normally when no work remains. A worker that runs before commit may find no work or process an unattempted photo in the previous active collection; it cannot process the pending collection.

Photos change every 15 minutes. Tap the photo to advance immediately and start a fresh 15-minute interval; the position survives a page reload. With 24 pictures, automatic rotation repeats every six hours. A missed automation, empty album, or interrupted upload keeps the last complete collection running.

Tapping the photo also reveals Settings and Apps. Tapping a widget or control does not advance the photo. Photos lets you adjust cropping and clock placement, including bottom left, center, and right. Weather and live activities rearrange around the clock. The web frame stays on while you are home with Sleep Focus off; Away and Sleep Focus still cover the display. Spotify opens when playback starts or resumes and, when automatically opened, returns to the photo frame after sustained pause or stop. Its delay matches the OLED: accumulated playing time, from five seconds up to five minutes. Resuming cancels the pending close; manually opened Spotify stays open. Returning to the frame keeps it there until the next playback start; photo/settings edits are allowed to finish first. Physical OLED motion dimming and sleep behavior remain independent.

If the collection does not arrive

Check the connection status in Apps → Photos. Verify that the server and Shortcut use the same token and that the photo URL ends in .convex.site. Run the Shortcut manually to locate the action that failed, then use the frame's sync control to check again.

New uploads never partially replace the current collection. The two most recent complete collections are retained; abandoned uploads expire after 48 hours.
